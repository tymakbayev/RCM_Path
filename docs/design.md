# Как устроен адрес

```
ключ (uuid, 16 Б) ──hash64(ключ, зерно)──► h                      G  порождается, не хранится
h ──► P: каскад битовых карт «ключ попал в ячейку один»             P  ≈3 бита на ключ, ранг за O(1)  ──► slot
slot ──► D[slot] = отпечаток (8 бит) | страница кучи (⌈log2 страниц⌉ бит)   R  остаток на ключ
SELECT … FROM t WHERE ctid >= '(page,0)' AND ctid < '(page+1,0)' AND k = $key    читает эту страницу кучи
```

- **Статический адрес не хранит ни ключей, ни дерева поиска.** Адресный файл (формат `JLMADR01`) — плоские массивы.
  Он открывается через mmap (файл отображается в память, читаются только нужные части), поэтому время открытия от N
  не зависит: 2,98 мс на 1 млн и 2,66 мс на 10 млн строк в A2.
- **Возвращённая строка — всегда запрошенный ключ.** Ключ сравнивается в самой строке. Совпадение отпечатка стоит
  одного лишнего чтения страницы, но не чужой строки. Отсутствующие ключи почти всегда отсеиваются по отпечатку ещё
  до SQL. Чтобы находилась каждая живая строка, адрес должен идти в ногу с таблицей — это обеспечивают
  [условия работы прототипа](results.md#условия-работы-прототипа).
- **Изменяющиеся данные (A4–A6).**
  - Новые строки идут в журнал хвоста. Запечатанные пакеты становятся маленькими адресами («прогонами»), а прогоны
    сливаются ярусами, как LSM-дерево из адресов.
  - Эти варианты хранят ещё и журналы прогонов с полными ключами (ключ 16 Б + страница 4 Б) для слияний. На пути
    поиска журналы не участвуют.
  - Большое слияние идёт ограниченными шагами: по хеш-секциям адреса (A5) или по хеш-партициям таблицы (A6).
- **Только точечный поиск по ключу.** Диапазоны и порядок по-прежнему требуют B-tree.
- **Это всё равно индекс** — статическая функция «ключ → страница», а не «индекс в 0 байт». Для произвольного
  размещения строк, не связанного с ключом, по примерно равномерно заполненным страницам информационная оценка —
  около log2(число страниц) бит на строку; для произвольной перестановки n различных строк по отдельным позициям —
  около log2(n) − 1,44 бита ([`experiments/STAGE1.md`](experiments/STAGE1.md) §2.1). В текущем формате номер
  страницы хранится отдельным полем, это и есть основная часть; каскад (≈3 бита) и отпечаток (8 бит) — накладные
  расходы. Если размещение связано с ключом (как в варианте Б из A2), оценка другая.

Как к этому пришли — этапы и их итоги:

| Этап | Что изменилось | Итог |
|---|---|---|
| STAGE1 | аудит и схема: совершенный хеш + отпечаток + номер страницы, граница log2 | [STAGE1_postgresql_branch.md](experiments/STAGE1_postgresql_branch.md) |
| A2 | sidecar к таблице PostgreSQL; дельта изменений — частичный B-tree | статика выполнена, динамика нет (дельта дорожает) |
| A3 | частая полная пересборка | работает, но цена пересборки на операцию растёт пропорционально N |
| A4 | дельта сама из маленьких адресов, ярусные слияния | расчётная цена обслуживания на 10M ниже, чем на 1M, но пауза большого слияния больше (18,5 против 5,0 с) |
| A5 | большое слияние шагами по хеш-секциям | полная пересборка разделена на шаги; пауза на 10M меньше, чем на 1M, но нужен рабочий файл |
| A6 | таблица разбита на хеш-партиции, шаг — одна партиция | рабочего файла нет, пауза 0,62 / 0,36 с |
| A7, A8 | цена самого партиционирования | на 1M ×1,23–1,25; на 10M в совместном прогоне знак обратный, причина не найдена |
