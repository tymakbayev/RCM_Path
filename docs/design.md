# Устройство адреса

```
ключ (uuid, 16 Б) ──hash64(ключ, зерно)──► h                      G  вычисляется, не хранится
h ──► P: каскад битовых карт «ключ попал в ячейку один»             P  ≈3 бита на ключ, ранг за O(1)  ──► slot
slot ──► D[slot] = отпечаток (8 бит) | страница кучи (⌈log2 страниц⌉ бит)   R  остаток на ключ
SELECT … FROM t WHERE ctid >= '(page,0)' AND ctid < '(page+1,0)' AND k = $key    чтение этой страницы кучи
```

- Статический адрес не хранит ни ключей, ни дерева поиска. Адресный файл (формат `JLMADR01`) состоит из плоских
  массивов и открывается через mmap (файл отображается в память, читаются только нужные части). Время открытия от N
  не зависит: 2,98 мс на 1 млн и 2,66 мс на 10 млн строк в A2.
- Возвращаемая строка всегда соответствует запрошенному ключу: ключ сравнивается в самой строке. Совпадение отпечатка
  стоит одного лишнего чтения страницы, но не приводит к выдаче чужой строки. Отсутствующие ключи почти всегда
  отсеиваются по отпечатку до SQL. Полнота поиска живых строк требует, чтобы адрес соответствовал таблице; это
  обеспечивают [условия работы прототипа](results.md#условия-работы-прототипа).
- Изменяющиеся данные (A4-A6):
  - новые строки записываются в журнал хвоста; запечатанные пакеты превращаются в маленькие адреса (прогоны), которые
    сливаются ярусами по схеме LSM;
  - для слияний хранятся журналы прогонов с полными ключами (16 байт ключа и 4 байта страницы); на пути поиска они не
    участвуют;
  - большое слияние выполняется ограниченными шагами: по хеш-секциям адреса (A5) или по хеш-партициям таблицы (A6).
- Поиск только точечный, по ключу. Диапазоны и упорядоченный обход выполняются через B-tree.
- Адрес является индексом в виде статической функции «ключ → страница». Для произвольного размещения строк, не
  связанного с ключом, по примерно равномерно заполненным страницам информационная оценка составляет около
  log2(число страниц) бит на строку; для произвольной перестановки n различных строк по отдельным позициям около
  log2(n) − 1,44 бита ([`experiments/STAGE1.md`](experiments/STAGE1.md) §2.1). В текущем формате номер страницы хранится
  отдельным полем и составляет основную часть адреса; каскад (≈3 бита) и отпечаток (8 бит) образуют накладные расходы.
  При размещении, связанном с ключом (вариант Б из A2), оценка другая.

## Этапы

| Этап | Изменение | Итог |
|---|---|---|
| STAGE1 | аудит и схема: совершенный хеш, отпечаток, номер страницы, информационная граница | [STAGE1_postgresql_branch.md](experiments/STAGE1_postgresql_branch.md) |
| A2 | адрес рядом с таблицей PostgreSQL; дельта изменений в частичном B-tree | статические критерии выполнены, динамический нет: дельта дорожает |
| A3 | частая полная пересборка | критерии выполнены; цена пересборки на операцию растёт пропорционально N |
| A4 | дельта из маленьких адресов, ярусные слияния | расчётная цена обслуживания на 10M ниже, чем на 1M; пауза большого слияния больше (18,5 против 5,0 с) |
| A5 | большое слияние шагами по хеш-секциям | полная пересборка разделена на шаги; пауза на 10M меньше, чем на 1M; требуется рабочий файл |
| A6 | таблица разбита на хеш-партиции, шаг слияния равен одной партиции | рабочий файл не нужен; самая длинная пауза 0,62 / 0,36 с |
| A7, A8 | цена самого партиционирования | на 1M ×1,23-1,25; на 10M в совместном прогоне знак обратный, механизм не установлен |
