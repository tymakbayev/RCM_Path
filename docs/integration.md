# Использование с собственной таблицей

Движок работает рядом с PostgreSQL как модуль на Python (sidecar) и подключается к серверу через стандартное клиентское
соединение. По ключу он вычисляет номер страницы и выполняет запрос, который читает эту страницу и проверяет ключ.
Изменения сервера не требуются; адрес хранится в отдельном файле.

## Пример

`rcm_address_engine/rcm.py` реализует статический адрес (вариант А из A2) для существующей таблицы с ключом `uuid`:

```python
import psycopg
import rcm                                   # из папки rcm_address_engine или с ней в sys.path

conn = psycopg.connect("host=localhost dbname=mydb user=me", autocommit=True)
info = rcm.build(conn, "public.items", "id", "items.adr")   # рядом создаётся описание items.adr.json
print(info["bytes_per_row"], info["verified_rows"])         # при сборке каждый ключ проверяется на свою страницу

with rcm.Address.open("items.adr") as addr:  # файл отображается в память (mmap)
    addr.check(conn)                         # та же база и таблица, таблица не переписана
    row = addr.get(conn, "2b0c6c1e-6f7d-4a3e-9a51-8c1d2e3f4a5b")   # кортеж или None
    row = addr.get(conn, some_uuid, fallback=True)                 # для строк, вставленных или перемещённых позже
    row = addr.get(conn, some_uuid, columns=["id", "name"])        # выбранные колонки
```

## Требования

При невыполнении условия `build()` завершается с ошибкой и объяснением:

- одна обычная таблица с хранением heap; отдельная секция допускается. Секционированный родитель, представление,
  таблица с наследниками и таблица с включённой защитой строк (RLS) не поддерживаются;
- ключ: колонка `uuid` с уникальными значениями; `NULL` не адресуются;
- подключение psycopg 3 с `autocommit=True`. Сборка читает таблицу одним снимком `REPEATABLE READ` под блокировкой
  `ACCESS SHARE`;
- права: чтение таблицы; суперпользователь не нужен.

## Семантика адреса

- Адрес соответствует снимку таблицы на момент чтения в `build()`. Строки, вставленные или перемещённые на другую
  страницу после начала чтения, по адресу могут не находиться. `get(..., fallback=True)` в этом случае выполняет
  обычный запрос по ключу: ответ остаётся верным, но поиск отсутствующего ключа стоит как обычный поиск. Обновления,
  при которых строка остаётся на своей странице (HOT, heap-only tuple), адрес не нарушают. При интенсивных изменениях
  адрес пересобирается.
- Обслуживание изменяющихся данных без пересборки (A4-A6) реализовано в скриптах экспериментов, где все записи
  проходят через движок.
- `VACUUM FULL`, `CLUSTER` и `TRUNCATE` переписывают таблицу. `check()` обнаруживает это в момент вызова; адрес
  требуется пересобрать. `check()` не блокирует последующий DDL и не различает разные кластеры с совпавшими номерами.
- Адрес и его описание (`items.adr` и `items.adr.json`) связаны контрольной суммой файла адреса; файл другой сборки
  `Address.open()` не принимает. Сумма записывается в последние 32 байта файла при сборке, при открытии читаются только
  они, поэтому время открытия не зависит от числа строк.
- Если по ключу существует другой индекс, планировщик может выбрать его вместо чтения страницы. План проверяется через
  `addr.query(conn, key)` и EXPLAIN или фиксируется настройкой `plan_cache_mode = force_custom_plan`, как в демо. В
  проверках с B-tree первичного ключа на той же таблице планировщик выбирал Tid Range Scan.
- Адрес закрывается (`with` или `close()`) до пересборки того же файла: Windows не заменяет файл, открытый через mmap.

## Проверка

`rcm.py`, `demo.py`, `rcm_pgtest.py` и `rcm_selftest.py` построены на функциях, которыми получены результаты A2-A8:
`a2_core.build_a`, `write_a`, `SidecarA`, разбор COPY и запрос поиска из `a2_pg`.

- PostgreSQL 18.7 (zip-сборка EDB), под суперпользователем и под ролью без особых прав:
  - `rcm_pgtest.py`: все проверки пройдены. Таблица с первичным ключом uuid; поиск и план запроса; HOT-обновление по
    счётчику сервера; перемещённая и новая строка; `VACUUM FULL`; отказ для неподдерживаемых таблиц;
  - демо на 5 000 и 200 000 строк.
- Без базы: `rcm_selftest.py`, все проверки пройдены.

Проверка на своей системе: `python rcm_pgtest.py` (нужна база с правом создавать таблицы).

## Формы интеграции

| Форма | Состояние |
|---|---|
| Модуль на Python рядом с PostgreSQL: эксперименты A2-A8, `rcm.py`, `demo.py` | реализован, проверен на PostgreSQL 18.7 |
| Обслуживание изменяющихся данных без пересборки | реализовано в скриптах экспериментов A4-A6, отдельный API не выделен |
| Метод доступа индекса на C (`CREATE INDEX … USING rcm`, WAL, MVCC, планировщик) | в этой работе не реализовывался |
