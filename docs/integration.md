# Подключение к своей таблице

Движок сейчас — **внешний модуль на Python рядом с PostgreSQL** (sidecar — «модуль сбоку»). Он подключается к серверу как обычный
клиент: вычисляет страницу по ключу и отправляет обычный SQL-запрос «прочитай эту страницу и проверь ключ». Сам
PostgreSQL об адресе не знает. Расширения внутри PostgreSQL (`CREATE INDEX … USING rcm`) пока нет — см.
[статус интеграции](#статус-интеграции).

## Пример

`rcm_address_engine/rcm.py` — API статического адреса (вариант А из A2) для существующей таблицы с ключом `uuid`:

```python
import psycopg
import rcm                                   # запускать из папки rcm_address_engine или добавить её в sys.path

conn = psycopg.connect("host=localhost dbname=mydb user=me", autocommit=True)
info = rcm.build(conn, "public.items", "id", "items.adr")   # один раз; рядом пишется items.adr.json
print(info["bytes_per_row"], info["verified_rows"])         # при сборке каждый ключ проверен на свою страницу

with rcm.Address.open("items.adr") as addr:  # файл отображается в память (mmap): открытие не зависит от числа строк
    addr.check(conn)                         # та же база и таблица, её не переписали (VACUUM FULL, CLUSTER, TRUNCATE)
    row = addr.get(conn, "2b0c6c1e-6f7d-4a3e-9a51-8c1d2e3f4a5b")   # кортеж или None
    row = addr.get(conn, some_uuid, fallback=True)  # если строку могли вставить или переместить после сборки
    row = addr.get(conn, some_uuid, columns=["id", "name"])         # только нужные колонки
```

## Что поддерживается

`build()` откажет с объяснением, если условие не выполнено:

- **одна обычная таблица** (heap — стандартное хранение строк PostgreSQL) — отдельная секция подходит; секционированный родитель, представление, таблица с
  наследниками и таблица с включённой защитой строк (RLS) — нет;
- **ключ** — колонка `uuid`, значения уникальны, `NULL` не адресуются. Другие типы ключей пока не поддержаны;
- **подключение** — psycopg 3 с `autocommit=True`. Сборка читает таблицу одним снимком `REPEATABLE READ` под
  блокировкой `ACCESS SHARE`;
- **права** — чтение таблицы; суперпользователь не нужен.

## Что означает адрес

- **Адрес соответствует снимку таблицы на момент чтения в `build()`.** Строки, вставленные или перемещённые на другую
  страницу после начала чтения, находить по адресу не гарантируется. `get(..., fallback=True)` тогда ищет обычным
  запросом по ключу: ответ верный, но отсутствующий ключ стоит обычного поиска. Обновления, при которых строка
  остаётся на своей странице (HOT — heap-only tuple update), адрес не ломают. Для изменяющихся таблиц пересобирайте адрес.
- Динамика без пересборки (A4–A6) пока работает только внутри скриптов экспериментов, где все записи идут через
  движок.
- **`VACUUM FULL`, `CLUSTER`, `TRUNCATE`** переписывают таблицу. `check()` обнаружит это в момент вызова, адрес нужно
  пересобрать. `check()` не блокирует последующий DDL и не отличит другой кластер с совпавшими номерами.
- **Адрес и его описание** (`items.adr` и `items.adr.json`) связаны контрольной суммой файла адреса: файл от другой
  сборки `Address.open()` не примет. Сумма записывается при сборке в последние 32 байта файла; при открытии
  читаются только они, файл целиком не пересчитывается — открытие по-прежнему не зависит от числа строк.
- **План.** Если по ключу есть и другой индекс, планировщик может выбрать его вместо страницы адреса. Проверяйте план
  (`addr.query(conn, key)` + EXPLAIN) или задайте `plan_cache_mode = force_custom_plan`, как в демо. В наших проверках
  с B-tree первичного ключа рядом планировщик выбрал Tid Range Scan.
- **Закрывайте адрес** (`with` или `close()`) до пересборки того же файла: Windows не заменяет файл, открытый через
  mmap.

## Как это проверено

`rcm.py`, `demo.py`, `rcm_pgtest.py` и `rcm_selftest.py` добавлены после эталонных прогонов. Они собраны из функций,
на которых получены результаты A2–A8: `a2_core.build_a`, `write_a`, `SidecarA`; разбор COPY и запрос поиска из
`a2_pg`.

- **На PostgreSQL 18.7** (zip-сборка EDB), под суперпользователем и под обычной ролью без особых прав:
  - `rcm_pgtest.py` — все проверки прошли: своя таблица с первичным ключом uuid; поиск и план; HOT-обновление по
    счётчику сервера; перемещённая и новая строка; `VACUUM FULL`; отказы для неподдерживаемых таблиц;
  - демо на 5 000 и 200 000 строк.
- **Без базы:** `rcm_selftest.py` — все проверки прошли.
- **Ревью кода** второй моделью.

Чтобы проверить у себя: `python rcm_pgtest.py` (нужна база, где можно создавать таблицы). Если что-то не сработает,
откройте issue.

## Статус интеграции

| Уровень | Что это | Состояние |
|---|---|---|
| Sidecar на Python | внешний модуль вычисляет страницу и шлёт PostgreSQL обычный SQL | **есть**: эксперименты A2–A8, `rcm.py`, `demo.py`; проверено на PostgreSQL 18.7 |
| Динамика без пересборки | журнал хвоста, прогоны, слияние шагами | есть внутри скриптов экспериментов A4–A6; отдельного API нет |
| Расширение PostgreSQL на C | `CREATE EXTENSION rcm; CREATE INDEX … USING rcm (id)`: метод доступа индекса, WAL, MVCC, планировщик | **нет**, следующий шаг |
