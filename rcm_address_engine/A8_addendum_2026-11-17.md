# A8 — приложение 2026-11-17 (после заморозки протокола, до кода)

Протокол `A8_protocol.md` (редакция 2, sha256 в `results/a8_protocol.sha256`) не меняется. Метки: ЗАМЕР, ВЫВОД,
ИСТОЧНИК.

## 1. Уточнение формулировок о кэше ОС (Codex 260, не блокирует)

Протокол в §5 (Д3, строки с сериями 5–6) говорит о чтении «через кэш ОС» как об установленном. Читать везде так:
«после вытеснения из буферов PostgreSQL; при условии, что страницы сохранились в кэше ОС». Это согласуется с §2.2 и
§7 протокола. В отчёте `a8_report.md` все выводы о кэше ОС формулируются условно.

## 2. Реализация после ревью кода Codex 262 (до самопроверки)

- **Режим атрибуции основного прогона.** «Поддержана», только если она поддержана и в самопроверке (п3а), и на
  сериях после вытеснения самого основного прогона; иначе «не поддержана».
- **Подготовленные запросы** (R2). Соединение серии оставляет автоматическую подготовку psycopg по умолчанию.
  Служебные команды идут с `prepare=False`, поиски — с `prepare=True`. После W проверяется положительно:
  - у `s` ровно один подготовленный текст по `s7`, выполненный не меньше |W| раз;
  - у `d` ровно `nparts` текстов по разным листьям, ни одного по родителю, каждый выполнен не меньше 6 раз.

  Раньше `prepare_threshold = None` отключал подготовку вообще, а пустой список проходил проверку. Отладочный прогон
  с той версией не доказывал подготовку.
- **Таблицы удаляются, только если их создал этот запуск** (R1). Отказ предусловия «таблиц нет» ничего не удаляет.
- **Правила пригодности применяются до сводок** (R3, протокол §4).
  - Блок с хотя бы одной ошибкой правильности или нарушением процедуры — НЕ УСТАНОВЛЕНО. Нарушения процедуры:
    `track_io_timing`, проверка подготовленных запросов, активность не той таблицы, невыполненное вытеснение. Эта
    часть строже протокола, который о нарушениях процедуры не говорит.
  - Больше 25% серий блока с непригодным атрибутированным I/O — τ, I и зависимые величины блока не используются.
  - Неподдержанная атрибуция — не ошибка.
- **Z выбирается из всех живых ключей листа**, без усечения первыми 50 000 (R4).
- **Буферы PostgreSQL по группам отношений** (`s7`, `p7`, `a7` — куча и индексы) снимаются в каждой точке C7 стадии A
  (обёртка), на границах блоков, вокруг сплошных прочтений, помех и пауз (R5).
- **`block_size` = 8192 проверяется** до измерений (R5).
- **`track_io_timing` по умолчанию `off` проверяется** в самопроверке. Без этого мутант N3 ничего не ломает.
- **Наблюдатель публикует свою статистику** (`pg_stat_force_next_flush`) перед каждым чтением счётчиков (R8). Журнал
  снятия: `flush` → `select1` → `obs_flush` → `clear` → `read`.
- **Отрицательный остаток чужих байтов** (меньше −1 блока) — «несогласованность учёта», атрибутированный I/O серии
  непригоден.
- **Учёт `pg_prewarm('read')` в `pg_stat_io` сверяется** с числом прочитанных блоков (повторное чтение через 1,5 с).
  Если доля учтённых байтов вне 0,95–1,05, байты воздействия — «недоступно или неполно», число блоков хранится
  отдельно.
- **Проверка расчёта** дополнена (R6):
  - E на двух парах с заранее посчитанными значениями;
  - правило «ошибка правильности → блок НЕ УСТАНОВЛЕНО»;
  - Д1 на трёх искусственных точках.
- **(п7) обёртки** проверяет в каждой точке C7: число операций I/U/D каждого маршрута равно числу операций уже
  применённых им пакетов (R6).
- **Состояние стадии B пишется по мере работы** (R7) в объект, который сохраняется при сбое. Там же текущий блок,
  набор, таблица и шаг. Соединение серии закрывается в `finally`. Ошибки очистки собираются, не заменяя исходную.
- **Мутант N11** (уточнение описания §4.1): вытеснение листьев `d` не выполняется (родитель хранения не имеет).
  Ловится остатком буферов (п6).

## 3. После повторного ревью кода Codex 264 (до самопроверки)

- **Помеха и контроль блока 3 проходят одну и ту же процедуру наблюдения** (R1): публикация статистики, снимки,
  память и буферы до и после, отложенное повторное чтение через 1,5 с. Различается только ядро: сплошное чтение
  `a7` или пауза длиной ядра последней помехи. Записываются время ядра `s` и полная длительность `total_s`.
- **Запись результата не мешает очистке** (R2). Очистка — во внешнем `finally`, ошибки записи собираются отдельно
  (`write_errors`) и не заменяют исходную причину. При сбое самопроверки сохраняется частичная стадия B. Расширения
  создаются внутри защищённой области.
- **Наблюдения каждой точки C7 стадии A проверяются** (R3): значения памяти и шесть числовых счётчиков буферов
  (`s7`, `p7`, `a7` — куча и индексы). В самопроверке это условие `all_ok`. В основном прогоне нарушение отмечается
  в статусе, прогон не останавливается: это наблюдение, а не правило правильности.

## 4. После проверки Codex 266 («можно запускать N10»)

Два неблокирующих замечания исправлены до прогона. После них самопроверка выполнена заново, так как хеш кода
изменился.
- **Созданные расширения журналируются сразу после `CREATE EXTENSION`.** Сбой на втором расширении не мешает удалить
  первое.
- **Если итоговый JSON основного прогона не удалось записать, команда завершается с кодом 3.** Очистка при этом всё
  равно выполняется.
